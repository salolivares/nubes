# Nubes

Electron desktop app for a photo publishing workflow. It converts a set of images to jpg and webp at
128, 640, 1280 and 2880px, tracks them as photosets in a local SQLite database, and uploads them as
albums to S3 with metadata.

## Working in a worktree

- Run `make setup` (or `pnpm install --frozen-lockfile`) first. A new worktree has no
  `node_modules`.
- Run `make check` (or `pnpm check`) before opening a PR. It runs typecheck, lint, test and
  format:check, the same checks CI runs. `make format` fixes formatting.
- In a linked worktree, dev data (SQLite DB, photosets, saved credentials, mock S3 bucket) lives in
  `.dev-data/`, and mock S3 is on by default, so two worktrees can run `pnpm start` side by side.
  `make clean-dev-data` clears it. `NUBES_USER_DATA` overrides the folder and `NUBES_MOCK_S3=1|0`
  forces the S3 mode. The main checkout keeps using `nubes-dev/` under the OS app data folder.
- Never run `pnpm package` (or `make package`, `pnpm test:e2e`, which packages) unless asked.

## Rules

- Use pnpm only, never npm or yarn.
- `src/main/drivers/s3/s3.ts` (real S3) and `src/main/drivers/s3/mock-s3.ts` both implement
  `IS3Provider`. When you change one, check whether the other needs the same change.
- Validate IPC arguments with Zod. Register main-process handlers with `handle()` from
  `src/main/ipc.ts`, which parses the schema and logs errors.
- Shared shapes (Zod schemas, inferred types, row types) live in `src/common/types.ts`. Main-process
  listeners and `types/api.d.ts` both import from there. Don't redefine them elsewhere.
- In `src/main/index.ts`, the dev `app.setPath('userData', ...)` call must stay the first code that
  runs after imports. Nothing that reads userData (`Storage`, `Database`) may run before it.
- Schema changes go in `src/common/db/schema.ts`, with a migration generated by `drizzle-kit` into
  `src/common/db/migrations/`. Migrations run at startup.
- `src/renderer/components/ui/` is generated by the shadcn CLI. Use the `shadcn` skill to change it.

## Source layout

Each `src/` directory is one Electron process with its own Vite config.

```
src/
├── main/                  # Main process (Node.js), vite.main.config.ts
│   ├── index.ts           # App lifecycle, dev userData path, single-instance lock
│   ├── ipc.ts             # handle(): Zod-validated ipcMain.handle wrapper
│   ├── drivers/
│   │   ├── database.ts        # Singleton: better-sqlite3 + Drizzle, runs migrations
│   │   ├── storage.ts         # Singleton: electron-store, safeStorage-encrypted credentials
│   │   ├── image-processor.ts # utilityProcess worker entry: sharp resize loop
│   │   └── s3/                # IS3Provider, real S3, MockS3, get/setS3Provider
│   └── listeners/         # IPC handlers: cache, debug, image-picker, image-processor,
│                          #   photoset, s3, storage, theme
├── preload/               # contextBridge APIs, one file per listener (vite.preload.config.ts)
├── renderer/              # React UI (vite.renderer.config.ts)
│   ├── routes.tsx         # Hash router
│   ├── pages/             # Home, NewUpload, ImagePicker, ImageProcessing, S3Upload,
│   │                      #   S3Summary, PhotosetDetail, BucketBrowser, *Settings
│   ├── components/        # App components, theme-provider.tsx, debug-bar.tsx, ui/ (shadcn)
│   ├── hooks/ stores/ lib/
└── common/                # Shared by all processes
    ├── constants.ts       # IPC channel names, DB_FILENAME, PHOTOSETS_DIR
    ├── types.ts           # Zod schemas and TS types
    └── db/                # Drizzle schema and migrations
```

`types/api.d.ts` declares the `window.*` preload APIs. `types/forge.env.d.ts` declares the Forge
constants (`MAIN_WINDOW_VITE_DEV_SERVER_URL`, `MAIN_WINDOW_VITE_NAME`).

Path aliases: `@/*` is `src/*`, `@client/*` is `src/renderer/*`, `@common` is `src/common`, `@ui/*`
is `src/renderer/components/ui/*`. They are defined in `tsconfig.json` and repeated in each Vite
config's `resolve.alias` (main only has `@` and `@common`).

## How the pieces talk

- **Typed IPC.** Preload files wrap `ipcRenderer.invoke()` and expose an API on `window`
  (`s3`, `photosets`, `storage`, `themeMode`, `imagePicker`, `imageProcessor`, `cache`, and `debug`
  in dev only). The renderer calls S3 through React Query.
- **Image processing.** `window.imageProcessor.resize()` sends to the main process, which forks
  `image-processor.js` as a `utilityProcess` and talks to it over a `MessageChannelMain`. Progress
  and completion go back to the renderer with `webContents.send()`.
- **Debug.** In dev, `listeners/debug.ts` and the renderer's debug bar can switch between real and
  mock S3, clear the DB, open the mock S3 folder and copy the DB path.

## User flow

1. **Home** (`/`) lists photosets from the DB.
2. **NewUpload** (`/new`) lists S3 buckets, then creates a photoset for the chosen one.
3. **ImagePicker** (`/bucket/:bucketName/picker`) takes files by drag and drop.
4. **ImageProcessing** (`/bucket/:bucketName/upload`) runs the worker and saves the outputs to the
   photoset.
5. **S3Upload** (`/bucket/:bucketName/s3`) edits metadata, then uploads the album or saves
   it as a draft.
6. **S3Summary** (`/bucket/:bucketName/summary`) shows the result. Drafts reopen from
   **PhotosetDetail** (`/photoset/:photosetId`).

## Packaging native modules

- **better-sqlite3** is bundled by `vite-plugin-native` in `vite.main.config.ts`.
- **sharp** loads platform packages with a dynamic `require()` that can't be traced, so it is
  externalized in `vite.base.config.ts` and copied by the `packageAfterCopy` hook in
  `forge.config.cts`, along with `@img`, `detect-libc` and `semver`.

Both rely on `asar.unpack: '**/*.{node,dll,dylib,so}'`.

## UI stack

React 19, React Router 6 (hash router, for `file://`), Tailwind CSS 4, shadcn/ui on
`@base-ui/react`, react-hook-form with Zod, Zustand for the upload pipeline, React Query v4, sonner
for toasts, lucide-react icons. Dark mode is the custom `src/renderer/components/theme-provider.tsx`.
